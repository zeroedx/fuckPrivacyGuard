### 4.3 未采用的具体技术原因

1. **构建架构不兼容**：本仓库刻意保持无 Gradle（`build.sh` 直接 `javac + d8 + aapt2`）。HyperCeiler 的界面全部建立在 Gradle 插件生态（AGP 9.4 + Kotlin）与 AndroidX 之上，任何直接移植都会把无 Gradle 架构推翻，并连带引入 `androidx.preference` 等运行时依赖。
2. **Miuix 依赖不可获取**：`fan.miuix:*` 从 HyperCeiler 自己的 GitHub Packages 拉取，需要私有凭据；这是硬性不可用条件，与是否愿意加依赖无关。
3. **注入开销约束**：本模块 dex 会被加载进 13 个系统进程，AGENTS.md 明确要求保持精简；AndroidX Preference + Room + Gson 的体积与启动开销不可接受。
4. **搜索实现路径不同**：HyperCeiler 搜索索引建在 AndroidX 偏好 XML 与 Room 上；本项目条目本就是内存中的 `Catalog.GROUPS`，直接遍历过滤即可，移植反而更重。
5. **AGPL-3.0 传染性**：HyperCeiler 为 AGPL-3.0。本项目为 GPL-3.0。直接复制其源码会触发 AGPL 的更强义务（含网络交互条款），属于"需要改变本项目整体许可策略"的情形。**按指令 5，此类复用需先报告并等待批准，本轮未做。** 因此本轮**未复制任何 HyperCeiler 源码或资源**，仅参考其公开可见的设计取向。

### 4.4 结论

界面栈（导航 / 首页 / 搜索 / 分类 / 主题 / 诊断）均为**自行实现的原生 Java View**，未移植上游代码、未引入任何新依赖。若后续希望直接复用 HyperCeiler 的 AGPL-3.0 实现，需要先决定并批准许可策略变化（以及是否接受 Gradle + AndroidX + 私有 Maven 凭据），届时再单独评估。

## 六、新界面结构

底部导航 6 个页面：

1. **首页**：品牌头图 + 版本；运行状态（LSPosed / 框架 / 作用域 / 分组数，读不到显示"未知"）；总开关；批量"全部启用 / 全部停用 / 全部重启"。
2. **分类**：13 组卡片，组开关与 LSPosed 真实作用域联动（`setOnToggleRequest`，等确认再切）；子项开关直写配置，打开子项时若不在作用域则顺手请求加入；"未在作用域，点此加入"行。
3. **搜索**：输入框实时过滤（名称 / 说明 / 包名 / Key），空结果显示空状态，无输入时列出全部分组作为入口。
4. **诊断**：模块信息、作用域清单（已加入 / 未加入 / 未安装）、运行记录（查看日志 / 分享日志 / 自检 / 清理日志缓冲）。
5. **设置**：通用开关（总开关 / 路径特征拦截 / 记录未拦截访问 / 隐藏桌面图标）、外观（跟随系统 / 浅色 / 深色）、规则（自定义规则 / 行为库状态）、日志。
6. **关于**：项目链接、LSPosed 模块页、Issues、上游项目、版本、检查更新、致谢与许可证、免责声明。

深浅色：跟随系统或手动固定；切换时整页重建（`Ui.palette()` 重新取色），弹窗随主题就地换色。外观偏好存于独立的 `pg_ui` SharedPreferences，**不进入 hook 侧读取的 `Settings.Global` 协议**。
